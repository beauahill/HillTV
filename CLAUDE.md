# CLAUDE.md

Notes for Claude Code working on HillTV, a personal tvOS IPTV player (UHF/Chillio style). Read README.md for the human-facing overview. There is also a Google TV port under `android/`; everything about it is in "Android (Google TV) app" below, and the rest of this file is about the Apple TV app unless it says otherwise.

## The big constraint: there is no Mac

Beau builds on Windows and Linux. GitHub Actions on `macos-26` is the compiler. The loop is: edit, commit, push, watch CI, read failures, fix.

```
gh run watch                         # follow the latest run
gh run view --log-failed             # just the failing step's log
gh workflow run build.yml -f ksplayer=true   # one-off KSPlayer build
```

The core package does build and test locally on Linux with a Swift toolchain, so put logic there whenever you can and test it before pushing:

```
swift test --package-path Packages/HillTVCore
```

Anything that imports SwiftUI, UIKit, AVKit or Security can only be compiled in CI. Keep those pushes small so a failed run points at one change. `swiftc -parse $(find App -name '*.swift')` catches syntax errors locally but does no type checking.

## Layout and architecture

```
App/HillTVApp.swift          @main, RootView (login vs shell), MainShell + Sidebar (the icon rail), Wordmark
App/Model/AppModel.swift     Session, engine choice, live format choice
App/Model/AccountStore.swift Keychain with UserDefaults fallback
App/Model/FavoritesStore.swift
App/Model/LoadState.swift    LoadState enum + LoadStateView placeholder
App/Model/EPGStore.swift     Short EPG per channel for Live TV and Home, plus a shared clock
App/Model/LiveTVModel.swift  Live TV selection: a pill (Favorites or a category group) plus a sub-selection
App/Model/CategoryVisibilityStore.swift  Hidden categories per account, kept on sign out
App/Model/ScoreboardStore.swift  Scores for Sports and the channels matched to each game
App/Model/ChannelOrderStore.swift  The viewer's order for channel lists, per account, kept on sign out
App/Model/MultiviewStore.swift  The multiview's channels and whether it is on screen
App/Player/                  PlayableItem, PlayerView, AVPlayer + KSPlayer engines, LivePreviewView
App/Views/Theme.swift        Color/type tokens, button styles, Eyebrow, Pill, ProgressBar, FocusAwareProgressBar, FlowLayout, Backdrop
App/Views/                   Home (the billboard page), Multiview, MoveChannel (Move mode), Search, Login, LiveTV (pills, chips, rows, detail pane, category picker), SportsViews (game rows, scoreboard pane, channel picker), CategoryManager, Guide, Movies + MovieDetail, Series (+ detail), Favorites, Settings, shared components (Rail, PosterCard, ChannelTile, LiveNowCard, ChannelNameLabel, CategoryNameLabel)
App/Model/WatchHistoryStore.swift  Continue watching, per account, cleared on sign out
Packages/HillTVCore/         No UI imports. Builds on tvOS, macOS, Linux.
```

Patterns to keep:

- Watch history stores IDs and rebuilds stream URLs with `movieURL(streamID:)` / `episodeURL(episodeID:)`. Never persist stream URLs: they contain the password.
- Search is a `fullScreenCover` over the shell, not a section: `MainShell.railSelection` opens it and leaves the current section selected. Anything that uses `.searchable` needs the full screen width on tvOS; don't put it back beside the rail. While the cover is up `MainShell` swaps the section for `Color.clear`, so nothing behind it holds a connection or polls. `AppModel` is passed into the cover explicitly.
- Each browse section (Home, Search, Live TV, Guide, Movies, Series) has an `@MainActor @Observable` model held as `@State` in `MainShell` and passed into the view, so switching sections in the rail keeps categories and caches. Models cache per category and drop late responses if the user moved on.
- Styling goes through `App/Views/Theme.swift`: color and type tokens, `TVRowButtonStyle` (rows), `TVActionButtonStyle` (actions, season chips), `TVPillButtonStyle` (the big Live TV pills), `TVChipButtonStyle` (filter chips), `TVCardButtonStyle` with `PosterCard` and `LiveNowCard` (cards). Blue is for focus, selection and progress; red only marks "live". A focused row fills blue with dark text, so anything inside one must flip color too (`tvSecondary()`, `FocusAwareProgressBar`). Use `ScrollView` + `LazyVStack` with these styles instead of `List`, whose focus platter fights the custom rows. To change the palette or type, edit the tokens at the top of `Theme.swift`; nothing else hardcodes colors.
- The rail (`Sidebar` in `HillTVApp.swift`) never changes its layout. Buttons stay icon-sized and the expanded panel, highlight and labels are drawn outside their frames, over the content. Keep it that way: the focus engine works from frames, and this keeps them identical collapsed or expanded. Menu on the rail goes to the content: SwiftUI can't move focus into a section whose views `MainShell` doesn't know, so `leaveRail()` disables the rail for 200 ms and the focus engine picks the content. `RailButtonStyle` must not react to `isEnabled`, or the rail would flicker when this happens.
- Guide, Movies and Series use `CategoryColumn`, which selects on focus with a 350 ms debounce, so up/down on the remote browses without clicking. Live TV is different: its pills and category chips select on click, because stepping across a row shouldn't reload the list at every stop.
- Live TV groups the provider's categories into pills with `CategoryGroup.classify` in core, which is keyword matching on the category name. A foreign country or language marker wins over a topic, so "FR | SPORT" and "LATINO SPORTS" go to World, not Sports (and their channels are not used for matching games); English-speaking markers like "US" and "UK" are ignored, so "UK | NEWS" is News. Every category lands in a group; unknown ones go to More. `LiveTVModel.groups` is stored and refreshed in `reconcileSelection()`, not computed per render. To fix a category that lands in the wrong group, add a keyword and a test case there. `LiveTVModel.Selection` is a pill plus a sub-selection: a provider category ID, `allID` (the group's channels merged, deduplicated by stream ID) or `gamesID` (Sports only). Favorites is a pill whose channels come from `FavoritesStore`.
- Channel names: `LiveStream.name` is always the provider's text. Favorites persist the whole struct, and `GameMatcher` and `SearchIndex` work on the raw name, so never store a cleaned one. For display, use `stream.displayName` (`ChannelName` in core) through `ChannelNameLabel`, or `.title` alone for a player title or a line of text. `ChannelName` only cuts what it is sure of: a known country or language marker followed by a separator, and quality labels at the end; anything else stays, and an empty result falls back to the whole name. Words that are also names ("RAW", "SD") count as labels only when bracketed or superscript. Any new screen that shows a channel name must use it too. Set `inFocusRow` on the label inside rows that fill blue on focus, and leave it off inside cards, which keep their text color.
- Guide favorites: `GuideModel.favoritesID` is a stand-in category ID. `select()` returns before the cache and the network for it, and `GuideView` reads the rows from `FavoritesStore`, not the model, so a removed favorite disappears at once. `CategoryColumn` is unchanged; the view puts the entry in front of the visible categories.
- Channel order: `ChannelOrder` in core keeps, per provider category, only the IDs from the top of the list down to the lowest row a move touched; the rest follows the provider. Don't store whole lists: UserDefaults is small and a category can hold thousands of channels. `LiveTVModel.streams` and `GuideModel.channels` are stored already ordered and re-ordered in `applyOrder()` (after a move, and on appear, since the other screen can reorder the same category), never sorted per render. Favorites are not in `ChannelOrder`: their order is the array in `FavoritesStore`. "All" and Games in Live TV are built from several categories and can't be reordered. Move mode (`MoveChannelView`) is a full-screen cover whose rows are slots identified by position: up and down are plain focus moves, and the moving channel is drawn in whichever slot has focus. Keep it that way. Catching the remote's arrows while holding the list still would need `onMoveCommand` to fire when focus has nowhere to go, which has never been tried on the TV.
- Multiview: `MultiviewStore` on `AppModel` holds the channels and `isShowing`; `MainShell` presents `MultiviewView` as a cover. It is opened from hold-Select menus, 350 ms after the pick so the menu can close. The section behind is left up so it keeps its place, which means anything in a section that holds a connection or polls must check `app.multiview.isShowing` (Live TV's preview and scores do). Tiles are `LivePreviewView`, AVPlayer with the HLS URL; its defaults are the preview's and the multiview passes its own. (The MPEG-TS trial swaps in `KSPlayerTileView`; keep its stub in step, like `KSPlayerEngineView`'s.) Anything in the multiview that needs focus must be a cover, not a panel over the grid: focus goes into a cover by itself and had to be steered into a panel. A cover opened as the multiview itself opens is held back until `settled`. Every tile is a connection: `Multiview.tileLimit` in core caps them by the account's `max_connections` (four at most, and four when the panel doesn't say), unless the viewer picked "Try anyway" (`AppModel.multiviewIgnoresLimit`), which is off by default and must stay a choice: don't drop the cap or treat a reported 1 as unknown. One channel always plays; the question is asked when a channel would go past the count. Layout is a real `Layout` (`MultiviewLayout`) placing `Multiview.frames`, not offsets, so the focus engine sees tiles where they are drawn. It stays inside the safe area; a TV's overscan cut the focus ring off when it didn't. A full-screen tile is the same view given the whole area, with the others hidden and disabled underneath but still playing, so nothing reconnects. `Multiview.pictureCap` sets `preferredMaximumResolution` per tile; it only matters if the provider's HLS has more than one quality, which has not been checked for Beau's provider. Don't add "Add to Multiview" inside Search without thinking: Search is itself a cover and the multiview cover is attached to the shell under it.
- Home: `HomeView` is the billboard page (built as "Discover" beside the old Home, which it replaced). `HomeModel` holds the rails, the navigation path and a cache of movie details. The billboard shows the last tile focus rested on (`.task(id: focus)`, 250 ms; a continue-watching tile is held by ID and read from the store when drawn or played, because the entry changes as it plays) and fetches a movie's details 400 ms after that, once per movie. Its height is fixed and blank lines hold the text rows, so the rails don't move. Tiles are Buttons that append to the path, not NavigationLinks, so each can carry a focus value. `HeroArt` needs its `.id(url)`: without it the last picture stays up when the next item has none.
- Category names: `XtreamCategory.name` is always the provider's text; grouping (`CategoryGroup.classify`), hiding and saved orders work on the raw name and the ID. For display use `category.displayName` (`CategoryName` in core) through `CategoryNameLabel`, or `.title` / `.line` where a plain string is needed. It cuts only forms seen on Beau's provider; add a real example to `CategoryNameTests` before adding a rule. The tags must stay visible wherever categories sit side by side, because two can differ only by tag. The label's tags inherit the name's color at lower opacity, so they need no focus handling.
- Hidden categories: models keep every category and expose `visibleCategories`; views only ever use the visible ones. Each model's `reconcileSelection()` runs on appear, because categories can be hidden in Settings between visits. `HomeModel` rebuilds its rails when the hidden set changed. Search filters results by category. Favorites and continue watching are never filtered. Any new screen that lists categories or their contents must do the same.
- Sports scores come from ESPN's public scoreboard feed (`Scoreboard` and `ScoreboardClient` in core). It is unofficial and keyless, so treat every failure as "no scores" and fall back to plain channels; never show the user an error for it. Poll only while games are on screen (`LiveTVView.gamesActive`). Team logos load from the feed at run time; never commit them, the repo is public.
- `GameMatcher` ties a game to channels from text alone. Both teams named in a channel name or guide listing is a sure match; a network name alone is not, because many channels share one. Tune directly only on exactly one sure match and open `GameChannelPicker` otherwise. Don't loosen this without device results: a wrong silent tune is worse than a list. Matching goes through `GameMatcher.ChannelIndex`, which narrows each game to channels that have the first word of a team name or network; `sweep(for:in:)` checks every channel and exists so the tests can hold the narrowed result to it. Any new way to match must either keep that true (every match needs a word from `GameTerms.required`) or change `required`.
- `EPGStore` (held by `MainShell`, shared by Live TV and Home) fetches short EPG for rows that stay on screen 300 ms, four requests at a time, and caches results including empty ones. `EPGSchedule.needsFetch` in core decides when to ask again. Views read `epg.now`, which ticks every 30 s, instead of `Date()`, so progress moves without each row running a timer. Guide still has its own fetch queue; fold it into `EPGStore` when Guide moves to XMLTV.
- Playback settings (`PlaybackSettings` in core, `AppModel.playback`, applied in `AVPlayerEngineView`). The defaults must leave the player exactly as it was before the settings existed; only a non-default choice may change it. On AVPlayer, live buffer and live delay are one lever: a live stream can't hold more ahead than it plays behind the live edge, so `liveBufferSeconds(offsetTarget:)` caps the buffer by the chosen distance. The distance uses `configuredTimeOffsetFromLive`, set once per item after `recommendedTimeOffsetFromLive` is known, then a seek to positive infinity. These settings only trim the player's share of the delay. Most of it is the provider's HLS packaging; the real cut is raw MPEG-TS through KSPlayer (roadmap 2). KSPlayer and the live preview ignore these settings for now. The settings decode leniently, so add new ones the same way.
- Live preview: `LivePreviewView` is always AVPlayer with the HLS URL, whatever the main engine is. `LiveTVView.runPreview` owns its lifetime through `.task(id:)`. The preview must never hold a connection it can't be seen using: keep the stops for player open, Move mode, multiview, scene inactive and idle timeout if this is reworked.
- `AppModel` goes in the environment. `.playerCover(item:)` presents the player and passes engine and user agent explicitly rather than relying on environment propagation into the cover.
- Player engine abstraction: `PlayerView` picks AVPlayer or KSPlayer. Only its black background and the Apple player ignore the safe area; KSPlayer's view must stay inside it, or its control bar runs off the screen. `KSPlayerEngineView.swift` has a `#if canImport(KSPlayerUI)` stub so nothing else needs conditional compilation; keep the stub's signature in step with the real view. The Settings choice is about live channels only, and the Apple player is always its default, even in a build that includes KSPlayer. Movies and episodes don't follow it (`PlayerView.usesKSPlayer`): they use the Apple player when it can open the file, because it has the native transport bar, and KSPlayer for file types it can't open (`MediaContainer` in core is a list of what the Apple player opens: mp4, m4v, mov, m3u8). A movie or episode the Apple player fails to start gets one try in KSPlayer before the error screen (`onFailedToStart`), because the panel's `container_extension` can be wrong or missing; a failure after playback started is always an error. In KSPlayer, resume uses `KSOptions.startPlayTime` and progress comes from the coordinator's `onPlay` (how often it fires was not measured; assume often) through `ProgressTracker` in core: one save per ten seconds, nothing from before the resume point is reached, and the last position kept in our own box because KSPlayer clears its callbacks as it closes. Every change to the player now needs both builds green: `gh workflow run build.yml --ref <branch>` and the same with `-f ksplayer=true`. They no longer cancel each other.
- KSPlayer's core is a prebuilt binary; its API is in `Sources/KSPlayer.xcframework/tvos-arm64/KSPlayer.framework/Modules/KSPlayer.swiftmodule/arm64-apple-tvos.swiftinterface` in their repo, and its SwiftUI layer is source under `Sources/KSPlayerUI/SwiftUI`. Read those before changing `KSPlayerEngineView.swift` or moving the pinned commit. Its free build is GPL-3.0, which is why this repo is GPL-3.0 as of v0.3.0-rc1 (Beau's decision, Nov 2026) and releases are built with KSPlayer (`USE_KSPLAYER=true`). One thing is still Beau's call, so ask first: making KSPlayer the default player. Don't add code or assets under a license that GPL-3.0 can't include.
- Live URLs: AVPlayer gets `.m3u8`, KSPlayer gets `.ts` unless the panel's `allowed_output_formats` lacks it. See `AppModel.liveFormat`.
- Xtream JSON is messy. All decoding goes through the `lenient*` helpers and `LossyArray` so a bad row or a `"1"` vs `1` never fails a whole list. Add a test with a realistic ugly payload for every new endpoint.
- Credentials: query items need `+` encoded as `%2B` (`fixPlusEncoding`), path segments need `/?#;` encoded (`encodePathSegment`). Both are tested; don't rebuild URLs by hand elsewhere.

Swift settings: Swift 6 compiler, Swift 5 language mode (`SWIFT_VERSION: 5.0`). Move to Swift 6 mode later, once the app compiles and runs.

### Patterns to keep

- Covers stack. `HillTVRoot` nests one `Covered` per entry in `CoverHost`, so a page opened over the multiview (its list, the connection question, a menu) leaves the tiles composed and playing. Swapping one cover for another (a menu that opens Move) passes `coverKey`, so focus goes into the new one and still returns to the control from before the first. The hold menu is the topmost cover, declared after the shell.
- The section under a cover keeps running. Anything there that holds a connection or polls must stop itself: Live TV's preview checks Move, the menu, the multiview and the player; scores check the multiview.
- Multiview tiles are `LivePreview` (one ExoPlayer each) inside one `Layout` keyed by stream ID, so going full screen only moves a tile and never rebuilds its player. A decoder failure (`isDecoderError`) reads as the device's limit, not the provider's.
- Keep the two cores in step. A change to `Packages/HillTVCore` gets the same change in `android/core`, and the test with it. Kotlin names match the Swift ones (`EPGSchedule`, `VODStream`, `GameMatcher`) so they can be read side by side. URLs are plain strings in the Kotlin core, and the value types are immutable: `history = history.record(entry)` where Swift mutates in place.
- Sizes are the tvOS numbers halved. tvOS lays out on 1920 x 1080 points and a 1080p Android TV is 960 x 540 dp, so 28 pt text is 14 sp and both draw the same pixels. `ui/Theme.kt` is the twin of `Theme.swift`; change a token in one, change it in the other.
- Lists load as a stream. `XtreamClient.getList` decodes one row at a time off the response (`decodeLossyList`) and never builds the whole JSON tree, because an Android TV app gets a few hundred megabytes of heap at best and a big provider's channel list would not fit as a tree. Don't replace it with "read the body, parse, map".
- The two URL encoders are written by hand (`encodeQuery`, `encodePathSegment` in `XtreamClient.kt`) and tested against Foundation's output. Don't swap in `URLEncoder` or OkHttp's builder: their character sets differ, and "+" in a password breaks.
- Everything focusable is a `FocusBox`. It draws its own focus, tells its content through `LocalFocused` (so text and progress bars can flip to dark on the blue fill), handles Select and hold-Select itself, and records itself in `FocusMemory`. It only takes keys while it has focus itself, not while something inside it does; before that, Enter typed in a text field was swallowed by the box around it.
- `Covered` is how one page sits over another: the player over everything, full-screen covers (`FullScreenCover`: Search, the category grid, the game channel picker, the category manager) over the shell, a detail page over its grid (`DetailStack`). The page underneath stays composed, so it keeps its scroll position; focus can't enter it while covered; and when the cover closes, focus goes back to the exact control that had it, from `FocusMemory`. Compose's own `focusRestorer` did not manage that through several nested groups. A control that changes under a cover must stay the same composable to get focus back: that is why the movie page has one button that says "Watch now" or "Resume" rather than two.
- Search takes its section down while it is open, as on tvOS. The control that opened it is gone when it closes, so `MainShell` puts focus back in the content itself, after the cover has finished closing.
- Back. `BackFirstLayout` in `MainActivity` takes the Back key before the system's keyboard service sees it, unless the keyboard is showing. Without it the first Back after the video view took focus did nothing, every time, in the emulator: the keyboard service swallowed it. Each cover adds a `BackHandler`; `MainShell`'s own is declared first so anything opened inside a section wins over it. Back at a section's root goes to the rail. Back on the rail leaves the app, which Google TV's guidelines ask for; this is the opposite of what Beau asked for on the Apple TV, so check he is happy with it.
- Focus moves by geometry, comparing whole rows by their centers. Two things follow. Down from a Live TV pill used to skip the chip row and land in the channel list, because the narrow list sits more squarely under a pill than the full-width chip row; each pill now names the chip row as its Down. And a list keeps its place when rows are added above, so the Sports list scrolls to the top when games arrive. Expect the same two traps in any new screen with a full-width row above a narrow column.
- Text fields are `TVTextField`. Focus landing on one does not open the keyboard; Select does. Up or Down while typing end typing and move focus on: Back with the keyboard up only hides the keyboard, and on the emulator's TV keyboard the arrows only reach the field once the keyboard is gone. Not checked on a real box's keyboard; if one passes arrows through while it shows, this would end typing early. Next carries on into the next field. To move focus when typing is done, use a `FocusRequester` in `onDone`: while the keyboard is up the window is shorter, what is below may be off screen, and "move down" wraps to the top instead.
- One player. `PlayerSession` wraps ExoPlayer, which plays HLS, raw MPEG-TS, mkv and mp4, so there is no engine choice and nothing like KSPlayer. Settings > Live stream format picks HLS (default) or MPEG-TS; `AppModel.liveFormat` falls back to what the panel allows. The live preview is always HLS. The player view needs real Android focus so the remote can drive Media3's own controls, and `controllerAutoShow` must be turned off before the player is attached or the controls flash up at the start.
- Live playback retries. A raw stream simply ends when the panel drops it, so `PlayerSession` asks again, up to three times in a row without a good stretch of playing in between, before showing the error. An ended stream needs `seekToDefaultPosition()` before `prepare()`; `prepare()` alone does nothing.
- Playback settings keep the tvOS rule: the defaults leave the player alone. "Player's choice" for the live buffer installs no `LoadControl` at all (on tvOS the default is 4 seconds; ExoPlayer's own is larger). Live delay only applies to HLS, where there is a live window: "Closest to live" replaces the media item's live target once the stream's own is known, "Keep up" seeks back to the live edge after a stall. "Closest to live" played without error in the emulator; "Keep up" has never been triggered. Neither has been measured against a clock.
- The login is encrypted with a key in the Android Keystore (`AccountStore`), with plain private preferences as the fallback, the same shape as Keychain with a UserDefaults fallback. Backups are off in the manifest so neither leaves the box. Favorites, history, hidden categories and settings are small JSON in preferences under the same keys the tvOS app uses.
- Cleartext http is allowed in the manifest for the same reason ATS is open on tvOS.
- The launcher banner and icons come from `python3 Tools/make_icon.py --android`. Don't edit the PNGs. Google TV shows only the banner, with no title under it, so the wordmark is in the picture.

### Where it differs from the Apple TV app

Beau has not seen this list yet. None of these were his picks; each was the nearest thing Android offers, and any of them can change:

- Back on the rail leaves the app (see above).
- No player choice; a live stream format choice instead.
- Hold Select opens a full-screen list of actions (`HoldMenu`), built like the other pickers. tvOS uses the system's context menu, which Android TV doesn't have. This look was not one of Beau's picks; offer mockups if he wants it changed.
- The multiview's MPEG-TS trial is ExoPlayer asking for `.ts`, not KSPlayer, since there is one player. A provider that offers no HLS gets MPEG-TS tiles; tvOS shows "Multiview isn't available" there.
- Search is a text box at the top of a full-screen page; Select on it opens the TV's keyboard. tvOS keeps its keyboard on screen.
- The player's controls are Media3's stock ones with the title drawn over the top. They don't match the app, the same complaint as KSPlayer's.
- The rail sits against the screen edge, as the Control Room mockup had it. On tvOS the safe area pushes it in.
- Down from a pill lands on the selected chip, and coming back to a row lands on the selected item. tvOS picks the nearest.
- No Top Shelf and no layered icon; a flat banner instead.

### CI and installing

`.github/workflows/android.yml` tests the core and builds the release APK on Linux when something under `android/` changes, and uploads it as a run artifact. It must never attach anything to a release: atvloadly picks the IPA out of each release by the word "hilltv" in the file name, and a release with a second matching file, or with no IPA, can stop the Apple TV updating. Read `match.go` in atvloadly before changing that.

Two things are Beau's call and are not done. First, a signing key: without the `ANDROID_KEYSTORE_*` secrets every CI build is signed with a throwaway key and can't be installed over the last one. Second, `build.yml` still runs on every pull request and every push to `main`, so merging Android-only work builds a new IPA and publishes a `build-N` prerelease that changes nothing for the Apple TV. Adding `android/**` to its `paths-ignore` would stop that; it touches the release pipeline, so ask first.

Installing is `adb install` over the network; the README has the steps. Which box Beau has, and whether he wants something that updates by itself the way atvloadly does, has not been asked.

The emulator used for testing is the SDK's own (`emulator`, system image `android-34;android-tv;x86`, AVD `hilltv_tv`), started with `-no-window -gpu swiftshader_indirect` and driven over adb. It crashed once after about twenty minutes of video. It and its image take about 15 GB (`~/Android/Sdk/system-images` is 13 GB of that, plus `~/Android/Sdk/emulator` and `~/.android/avd`) and can be deleted when no longer wanted.

## tvOS gotchas

- No WebKit on tvOS. Web-based players (IPTVnator, PWAs) cannot be embedded; port logic instead.
- UserDefaults is capped around 500 KB and Caches can be purged. Keep channel lists and EPG in memory or Caches and refetch. Persist only small things (favorites, settings). For durable sync across Apple TVs, use iCloud key-value storage later.
- AVPlayer plays HLS and mp4 only. Raw MPEG-TS and most mkv need KSPlayer. A KSPlayer IPA is about 23 MB against 1.3 MB without it.
- Focus engine: everything interactive must be a `Button`, `NavigationLink` or have `.focusable()`. Test focus paths, not just looks.
- Menu/Back button: confirm on device that it dismisses the full-screen player from both engines. If AVPlayerViewController swallows it, add `.onExitCommand` handling.
- ATS is wide open (`NSAllowsArbitraryLoads`) because most panels are plain http. Fine for sideloading.
- Installing with atvloadly can sit at 100% and never finish, and new icon or Top Shelf art can fail to appear. Both happened in Nov 2026 and both were fixed by restarting the Apple TV. Try that before suspecting the build.
- App icon and Top Shelf images live in `App/Assets.xcassets/App Icon & Top Shelf Image.brandassets` and are named by `ASSETCATALOG_COMPILER_APPICON_NAME` in `project.yml`. The icon is "Sunrise" (Beau's pick of four): three layers, sky at the back, a white sun with a play triangle, two blue hills in front. Don't edit the PNGs by hand; change `Tools/make_icon.py` and run it (needs Pillow, plus google-chrome and a network connection for the Top Shelf wordmark, which uses Inter). CI fails if the built app has no `Assets.car`, and prints the icon entries from Info.plist and the assets inside `Assets.car`. Beau prefers PNG artwork with solid, bold shapes. On the TV (Nov 2026): the icon shows and Beau likes it, and the Top Shelf banner shows correctly. The banner did not appear until the Apple TV was restarted, so after installing a build with new icon or Top Shelf art, restart the box before judging it. Not yet confirmed: the layers shifting when a thumb slides on the clickpad with the icon in focus (the effect follows touch, not tilting the remote). CI shows the built app contains "App Icon" as an `ImageStack` with all three layers, so check after a restart, compare with another app's icon, and check Reduce Motion is off before changing the art.
